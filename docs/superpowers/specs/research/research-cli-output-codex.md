# CLI output research — independent recommendation

2026-10-22. Primary docs/source below; local probes were read-only. Latch baseline: [output audit](output-consistency-audit.md). **Recommendation: retain JSON-first operation results; add an explicit global format contract covering failures too.** Do not make a future GUI infer its protocol from terminal allocation.

## Findings and recommendation (one-page brief)

The useful distinction is **result formatting, diagnostic formatting, and interaction policy**. Most surveyed CLIs expose JSON on selected commands, not a universal subprocess protocol. Even AWS's global output option does not make parser failures JSON. Terraform's versioned event stream and Stripe's split non-interactive login are stronger integration models than parsing terminal copy. See the comparison table for exceptions and sources.

**Output rule.** Operations retain JSON on stdout in every environment. Add global `--format=json|text|jsonl`, with `LATCH_FORMAT` as an optional lower-priority override; selection must happen before argument-error reporting. TTY controls decoration and prompts, not operation data. Explicit JSON also controls stderr and disables prompts, pagers, ANSI and browser launching. Text mode is an explicit human renderer. Preserve help/version/skill, logs, raw page text and TUIs as documented exceptions; reject incompatible format requests instead of silently returning text. A GUI should always request a format explicitly.

**Error contract.** In JSON mode, emit one stderr object: `{"error":{"code":"not_enabled","message":"Messages is off.","details":{},"retryable":false,"next":{"command":"latch plugins enable messages","actor":"owner"}},"exit_code":4}`. Keep current exits 0–5 and stable error codes; messages may evolve. Cover parser errors, setup failures and transport failures uniformly. No mixed progress prose on machine stderr; opt-in diagnostics go to a separate file. Do not promise an error object after abrupt termination. Distinguish execution failure from a successfully delivered operation result with a nonzero child exit; document both process and child statuses.

**Interaction and streams.** Keep interactive setup as a human orchestrator; offer a structured setup status/plan and explicit step commands for GUIs. Extend existing login events to include URL/code, expiry, required input, completion and failure; never require a GUI to scrape a QR or supply a fake TTY. `--non-interactive` must fail with actionable missing-input data, never silently consent. JSONL uses versioned, typed events with correlation IDs, timestamps and a terminal result/error event; the process exit agrees with that terminal event. Consumers must tolerate an incomplete stream on cancellation. Follow/audit streams remain bounded by backpressure, not an ever-growing UI history.

**Copy guide (8 rules).** (1) Lead with outcome, one short sentence. (2) Name the affected host/connector. (3) Give one concrete next action when needed. (4) Distinguish refused, unavailable, failed and skipped; never claim success from enablement alone. (5) State what ran or changed; avoid “Done” for partial setup. (6) Put codes, IDs and detailed diagnostics behind details/debug. (7) Use plain verbs; no apologies, celebration or repeated explanation. (8) Color/symbols reinforce words, never carry meaning alone; honor `NO_COLOR` and sanitize terminal control characters. These adapt [clig.dev](https://clig.dev/#output) and [Heroku's style guide](https://devcenter.heroku.com/articles/cli-style-guide), whose stderr/progress and prompt-bypass guidance fits latch.

**Concrete observed copy:** `Logged in as NAME.` (latch audit: short confirmation); `Run 'docker --help' for more information` (local parser probe: specific recovery); `Terraform has no command named "__latch_output_research_invalid__".` followed by `terraform -help` (local probe: diagnosis then action); `Terraform has been successfully initialized!` ([documented event](https://developer.hashicorp.com/terraform/internals/machine-readable-ui): clear outcome, although latch should omit the exclamation). Prefer these concise patterns to a paragraph after each step.

**Tradeoffs.** JSON-first is less friendly for occasional human inspection but preserves agents' existing interface; text renderers cost maintenance. Strict machine stderr makes trivial subprocess consumers reliable but needs a separate debugging channel. Versioned events add schema work; they avoid GUI coupling to prose. A generic `--yes` is convenient but conflates consent with non-interaction, so latch should require explicit choices. This is a proposed contract, not a claim about current latch behavior.

## Comparison table

“Text error” means prose, not a stable machine error shape. **No CLI-wide JSON error guarantee should be inferred from a success flag.** “Not established” marks a research limit, not proof that a feature does not exist. No format environment variable is asserted unless named. Normal success is exit 0; failure is nonzero unless a command documents an exception.

Local evidence, this session: subprocess-captured stdout/stderr and exits from `TOOL __latch_output_research_invalid__` for gh/kubectl/docker/terraform/tailscale/op/aws; repeated with `op --format json` and `aws --output json`. All had empty stdout and text stderr. Read-only help probes checked gh environment, Tailscale JSON schema warning and Docker events formatting. These are parser-path observations, not service-error tests. No login, deployment, installation, or credential inspection was performed; no scratch artifacts retained. Research was independent of the other expert.
