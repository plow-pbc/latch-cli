# Help for humans and agents: latch research

2026-10-22 · backend: codex · Research only; no implementation changes.

## Findings from primary sources

- **clap provides two levels already.** `about` is the short command description; `long_about` supplies its expanded replacement. Arguments have corresponding `help`/`long_help`. `-h` selects short help and `--help` long help. `after_help` appends free text and also appears in long help unless `after_long_help` replaces it. `help_template` controls presentation; it does not supply a semantic command schema. clap supplies a nested `help` subcommand unless disabled. Prefer these defaults over a second handwritten usage renderer. [Command API](https://docs.rs/clap/latest/clap/builder/struct.Command.html), [argument API](https://docs.rs/clap/latest/clap/builder/struct.Arg.html#method.long_help).
- **Offline reference and completion are generated views.** `clap_mangen` renders a `clap::Command` to ROFF, including subcommand manuals via `generate_to`; `clap_complete` generates shell completions from that command tree at build time or runtime. Neither supplies missing output/effect semantics. Generate release artifacts when useful; do not maintain separate flag lists or add a manual-authoring system. [clap_mangen](https://docs.rs/clap_mangen/latest/clap_mangen/), [clap_complete](https://docs.rs/clap_complete/latest/clap_complete/).
- **Established CLIs layer information, with different entry points.** ripgrep generates short `-h` and long `--help` from its flag definitions, with separate templates. uv intentionally makes `--help` condensed and `uv help COMMAND` expanded: an example of convention differing from clap defaults. Cargo supports nested `cargo help COMMAND`; jj offers command help plus conceptual keyword topics and an automatically generated online reference that explicitly defers to installed help. The useful commonality is discoverable depth and shared definitions, not identical switches. [ripgrep source](https://raw.githubusercontent.com/BurntSushi/ripgrep/master/crates/core/flags/doc/help.rs), [uv help](https://docs.astral.sh/uv/getting-started/help/), [Cargo help](https://doc.rust-lang.org/cargo/commands/cargo-help.html), [jj reference](https://docs.jj-vcs.dev/latest/cli-reference/).
- **Structured output is a contract, not scraped prose.** `cargo metadata` emits workspace/dependency JSON and documents format-version compatibility. GitHub CLI (Go, included as a UX comparison) provides selected result fields through `--json`; omitting its field argument discovers available fields. These are domain/result interfaces, not universal machine-readable CLI-help standards. Latch's command catalog is useful in its own right, but must explicitly describe what it guarantees. [Cargo metadata](https://doc.rust-lang.org/cargo/commands/cargo-metadata.html), [gh formatting](https://cli.github.com/manual/gh_help_formatting).
- **Agent formats have distinct jobs.** `llms.txt` is a proposal for website guidance and documentation links; `AGENTS.md` guides coding agents working in a repository. Agent Skills specifies YAML metadata plus Markdown instructions and supports progressive disclosure into references. MCP tools combine natural-language descriptions with input schemas and optional output schemas; annotations express hints such as read-only/destructive behavior, not authorization guarantees. These support concise discovery plus precise local reference, not a requirement to implement all four formats. [llms.txt](https://llmstxt.org/), [AGENTS.md](https://agents.md/), [Agent Skills](https://agentskills.io/specification), [MCP tools, revision 2025-06-18](https://modelcontextprotocol.io/specification/2025-06-18/server/tools).

## Recommendation for latch (under one page)

**Keep three views over explicit owners.** The inspected checkout already derives JSON inputs from clap, derives retry prose from `Effect`, and tests catalog coverage and example parsing. Preserve that design; do not rebuild it as a documentation framework.

| Fact | Single authored home | Views and pointers |
| --- | --- | --- |
| Commands, arguments, defaults, env, choices, constraints, concise descriptions | clap definitions in `cli.rs` | `-h`, `--help`, `help COMMAND`, JSON inputs; future completion/man artifacts |
| Command examples, effects, retry classification, owner/connector requirements | typed `help.rs` entries; Google permission grammar remains authoritative for delegated Google commands | Render into long help and `--examples`; serialize into scoped `help COMMAND --json` |
| Success/error shapes and exit/error identities | runtime response types and `failure.rs` | Catalog derives field information where practical; shared output description rendered in help; verify prose against representative responses |
| Agent workflow: identity, authorization, untrusted content, observe/act, recovery | concise embedded `latch/SKILL.md` | `latch skill`; root help points there; command help points to relevant workflow when needed |
| Host setup and deep connector concepts | README and existing area documents, with one canonical page per topic | Skill and command help link to those pages rather than retelling them |

**Presentation.** Keep `-h` short; make `--help` and `help COMMAND` identical expanded views of the same built command tree. Retain the custom `help` handler for JSON/examples and Google's delegated help. Long command help includes generated effects, retry guidance and a few catalog examples via `after_long_help`; root help needs only discovery pointers. Keep the skill small and procedural, using command references for syntax and per-command effects. Generate any necessary catalog excerpt inside `latch skill` from the same entries; do not generate a second command encyclopedia into checked-in SKILL.md. Distinguish the JSON catalog's format version from the binary version, with one current format and no compatibility adapter.

**Prevent drift.** Retain existing coverage/uniqueness, parser and output-field tests. Add behavioral checks that `help COMMAND` equals expanded `COMMAND --help`, scoped JSON excludes unrelated actions, generated examples/effects reach long help, and hidden/platform-only commands are represented correctly on each OS. Parse designated executable skill examples with clap, validate skill frontmatter, and check generated sections against their source. Parsing proves syntax only: test consequential claims about output, authorization and retries against real behavior near existing tests. Generate completion/man artifacts from the same enriched command tree if shipped.

**Delete duplication.** Replace `AGENT_HELP`/`MESSAGES_HELP` workflow essays with pointers; move unique essential content into the skill first. Replace overlapping `EXEC_HELP`, `DO_HELP`, `SERVE_HELP` material with clap argument explanations or catalog-generated examples/effects; preserve unique command grammar. Remove repeated flag/default/output inventories and command recipes from the skill and area docs once their canonical reference exists. Keep the useful help alias, structured catalog and skill. Add neither MCP nor llms.txt merely to solve subprocess help.

Validation: reviewed local sources and linked primary documentation. Documentation-only research; macOS and Linux test gates were not run.
